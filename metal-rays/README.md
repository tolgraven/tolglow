# Tolglow #538 direct Metal ray probe

The standalone macOS probe builds a primitive acceleration structure from 28 opaque triangles and calls Metal’s compute `intersector` for nearest hits and open-segment occlusion. Its 20 sightlines use Tolglow’s default Room receivers plus a screen with a rectangular opening and test panels. The checked-in expectations come from the application’s actual Clojure geometry functions. Linux reproduced the fixture and its CPU answers byte for byte. The macOS build, GPU dispatch and fixed-function trace await a physical Mac. [Issue #538](https://github.com/tolgraven/tolglow/issues/538) · [Metal ray tracing API](https://developer.apple.com/documentation/metal/ray-tracing-with-acceleration-structures)

## Run on a Mac

Use macOS 14 or later with full Xcode and its Metal toolchain. Xcode 15 provides the Apple9 family API. Use Xcode 26 or later for the explicit Apple10 family check. If Xcode reports a missing Metal toolchain, install the `metalToolchain` component for that Xcode. [Xcode components](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)

```sh
set -o pipefail
./run.sh | tee metal-538-parity.txt

trace_dir=$(mktemp -d "${TMPDIR:-/tmp}/metal-538-trace.XXXXXXXX")
CAPTURE_PATH="$trace_dir/fixture-sightlines.gputrace" RAY_REPEATS=4096 \
  ./run.sh | tee metal-538-capture.txt
open -a Xcode "$trace_dir/fixture-sightlines.gputrace"
```

`run.sh` prints model ID, chip/GPU identity, macOS build, Xcode and SDK versions, device family bits, source and executable hashes, and per-case observations. The default 20-ray run is a correctness check. The trace run repeats the GPU batch to make hardware counters visible. Optional trace files live under the caller’s scratch directory. Compile artifacts live in a temporary directory and are removed at exit.

| Device | Expected result on a supported OS |
| --- | --- |
| M4 MacBook Air, other M4 Macs, M3 Macs | `raytracing_api=1`, `apple9=1`, `status=hardware-eligible-parity-pass` if every case passes |
| M5 Macs | `raytracing_api=1`, `apple10=1` with a current SDK, same parity outcome if every case passes |
| M1 or M2 Macs | Default `status=portable`, exit 2. `ALLOW_API_ONLY=1 ./run.sh` can independently test the compute API and returns `status=api-only-parity-pass` if every case passes. |
| Other GPU or Linux | Portable path, exit 2 when the capability requirement fails. Build, capture and comparison errors return failure. |

Apple documents fixed-function traversal starting in Apple9, which includes A17 Pro, A18-series, M3 and M4. Apple10 includes A19-series and M5. This harness targets macOS. Native iOS/iPadOS device builds and captures are separate from this Mac receipt and from Safari or WKWebView execution. ## Fixture parity

Regenerate and compare the fixture using the two Git repositories. This reads the pinned blobs and leaves the checkouts intact. It uses the Clojure CLI or a `CLOJURE_CLASSPATH` containing the Clojure 1.12.7 and standard spec jars.

```sh
./verify-oracle.sh /path/to/tolglow /path/to/afterglow
```

- The generator loads Tolglow’s `receivers` and `surface-axes`, plus the Afterglow revision pinned by that Tolglow checkout. It calls `surface-raycaster` for distances, `segment-occluder` for open-end booleans, and `nearest-footprint` for ordered surface identity. It also reverses the CPU receiver list to verify that the exact coplanar and wall/floor ties follow input order. [Tolglow receiver source](https://github.com/tolgraven/tolglow/blob/c1fcdb9cffcf9329e736f29cd1cbe2efcce0cc8d/src/tolglow/rig/surfaces.clj#L15) · [Afterglow optics source](https://github.com/tolgraven/afterglow/blob/e1eb9ff50985a9e3e304b54ec7a97db735956c5a/src/afterglow/render/optics.cljc#L63)
- Readback checks the distance, hit identity, and occlusion against the CPU answers. The fixture covers a geometric cutout with a wall behind it, the included finite boundary and triangle seam, an oblique receiver, either face, direct misses, endpoints, and two types of ties. A raw Metal hit at an exact tie may identify any surface at the CPU’s closest distance. The printed `cpu_hit` shows the required canonical winner. The distinct near tie requires the actual closer surface even though a farther surface appears earlier in the rig. Production still needs analytic arbitration for ambiguous edges and ties before it can publish canonical identity.
- The standalone test uses finite planar rectangles and strict open segments encoded in Float32. At venue scale the representable precision around the segment end is coarser than the CPU’s 1 nm guard. The test uses conservative rounded endpoints and a finite 32 m first-hit bound. Preserve Float64 analytic handling for ambiguous endpoints, grazing cuts, unsupported or unbounded geometry, and nearly coincident planes at the actual publication boundary. Material alpha cutouts and analytic cone/ellipse footprints require their existing semantics. The screen cutout in this fixture is represented by missing triangles.

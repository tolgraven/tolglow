# Executed WebGL2 numeric experiment

Status: optional browser experiment implemented and exercised in a real WebGL2
context. It is independent of the show host, scheduler, studio preview, and
physical output. It demonstrates numeric shader execution and readback, not a
production GPU rendering backend or a hardware speedup.

The implementation is [resources/gpu/compute.js](../resources/gpu/compute.js).
The independent [test page](../resources/gpu/test.html) contains shader source and
expected values generated by `afterglow.render.ir/emit-glsl` and the actual
`compile-expression` CPU evaluator. No JavaScript expression interpreter replaces
the Clojure oracle.

For calibrated movement, see the [64/128-head shader and DMX readback experiment](moving-head-shader.md).

## Run it

Start the studio with its ordinary dry-run defaults, then open
`http://127.0.0.1:8500/gpu/test.html`. The page also works with a simple static
server, without starting the studio:

```sh
python3 -m http.server 8501 --bind 127.0.0.1 --directory resources
```

Open `http://127.0.0.1:8501/gpu/test.html` and press **Run correctness and timing
tests**. The page displays the full JSON report. From browser developer tools,
`await window.runGpuExperiment({counts: [1000, 10000], warmup: 3, samples: 12})`
runs the same tests; the latest result is retained as `window.gpuReport`.

The root server needs only static GET routes for `/gpu/compute.js` and
`/gpu/test.html`, with JavaScript and HTML content types. This page sends no
studio commands and connects to no output transport. No external scripts or
runtime dependencies are downloaded by the page.

## API and buffer contract

```javascript
import { createComputeRunner, UnsupportedError } from '/gpu/compute.js';

const runner = createComputeRunner(undefined, {
  maxElements: 100000,
  timeoutMs: 2000,
  pollIntervalMs: 0,
});
runner.compile(emittedShader); // JSON form of afterglow.render.ir/emit-glsl

const result = await runner.run({
  positions: new Float32Array([0, 0, 0, 1, 2, 3]), // two fixture/head positions
  params: { gain: 0.5 },                         // emitted parameter names
  timeMs: 1000,
  elapsedMs: 250,
  beat: 18,
  elapsedBeats: 6,
  meter: { beatsPerBar: 3, barsPerPhrase: 4 }, // required when musical nodes use them
  epoch: 4,
  frameId: 27,
  signal: abortController.signal,
});
// result.values: fresh owned Float32Array, four components per input position.
// result.timings: uploadMs, submitMs, fenceWaitMs, readbackMs, totalMs.
// result.frameId/result.epoch: caller-provided identity, unchanged.
runner.dispose();
```

`emittedShader`, its parameter values, and the abort controller are supplied by
the caller. Metadata must contain `source`, `type`, and `uniforms`, as produced
by the current Clojure emitter. Supported types are `number`, `vec2`, `vec3`, and
`vec4`. A dedicated canvas can be passed instead of allowing the runner to create
one. Do not share its WebGL state with a scene renderer.

Each invocation evaluates one expression for every position, preserving input
order. Scalar results occupy RGB with alpha 1; vec2 results occupy RG with B=0,
A=1; vec3 results occupy RGB with A=1; vec4 returns all components. The returned
view has exactly `count * 4` elements; its backing array may include unused
texture padding. That array belongs to the result and is never recycled into a
later frame. The runner does reuse its private GPU resources between calls.

Parameters and clocks are shared uniforms for that invocation. Musical IR nodes
`:beat`, `:bar`, and `:phrase` bind explicit captured `beat`/`elapsedBeats`; bar and
phrase divide by the supplied positive finite meter. They are continuous phases,
not rounded indices. Only musical inputs requested by the emitted metadata are
required; missing or invalid requested values reject before GPU submission.
Positions vary per head. There is no per-head parameter texture, effect-state
feedback, fixture calibration, multi-effect blending, channel packing, or output
transport in this experiment. Those remain host/runtime responsibilities.

The caller must check epoch and frame identity before accepting output. Returning
those tags does not by itself prevent a stale result from being applied after a
show reset. Abort superseded work and reject results for old epochs. The browser
is never an authoritative link in the physical light-output path.

## Execution path

1. Require WebGL2 and `EXT_color_buffer_float`; unsupported contexts report an
   `UnsupportedError` instead of silently reducing numeric precision.
2. Compile the emitted fragment shader with a small fixed vertex shader. Each
   vertex becomes one point at the center of one output texel. Its `v_position`
   is the corresponding fixture/head position. Existing emitted GLSL needs no
   shader-source rewriting or new Clojure API.
3. Allocate an RGBA32F target and pixel-pack buffer, bounded by `maxElements` and
   the context's texture-size limit. Validate finite float32 inputs before upload.
4. Upload positions and uniforms, render the points, and enqueue `readPixels`
   into the pixel-pack buffer. Blending, depth/stencil tests, scissor, culling and
   dithering are disabled for this numeric pass.
5. Insert `fenceSync`, flush, and poll `clientWaitSync` with a zero GPU wait timeout
   after yielding the browser event loop. No `gl.finish()` or blocking spin wait
   is used in the runner.
6. Once the fence signals, copy the completed pixel-pack buffer using
   `getBufferSubData`. Reject nonfinite outputs, then return a typed view and
   measurements. A fence does not eliminate CPU copy time; it makes readiness
   explicit before that copy.

Only one frame can be in flight per runner. Concurrent calls receive a `busy`
error, so clients cannot accidentally build an unbounded GPU queue. Compile a
replacement when idle; failed compilation/linking retains the prior good
program. Compilation itself can block and is excluded from steady-state timing.

## Cancellation, failure, and fallback

Errors expose `code` and structured `details`. Expected codes include
`unsupported`, `invalid-input`, `invalid-shader`, `shader-compile`, `shader-link`,
`allocation`, `webgl-error`, `busy`, `aborted`, `timeout`, `context-lost`,
`nonfinite-output`, `not-compiled`, and `disposed`.

Aborting discards the result; it cannot retract GPU commands already submitted.
Their order remains within the owned WebGL command stream. A later invocation
can run after cancellation. The wait deadline also rejects a fence that signals
after that deadline, including when the event loop was suspended. `timeoutMs`
bounds fence waiting, not synchronous shader compilation or the entire frame;
the application must enforce its own complete-frame deadline.

Context loss rejects pending output. Dispose the old runner and create a fresh
one, using a new canvas or after the original context is restored. Disposal is
idempotent and invalidates further calls. The caller chooses whether to evaluate
on the CPU, reuse the last accepted preview frame, or show an unavailable status.
There is deliberately no hidden fallback that changes the authoritative backend.

## Numerical evidence

The checked-in page includes eight expressions and 31 explicit positions per
case, for 992 compared RGBA components. It exercises constants, position
components, absolute/elapsed time, captured beat/bar/phrase phases with a 3×4
meter, arithmetic, clamping, scalar uniforms, vector
uniforms, and vec2/vec3/vec4/scalar output layouts. The larger timing cases tile
the same explicit position/oracle pairs; every returned component is compared
after every warmup and measured invocation, outside the recorded timing interval.

Testing on 2026-11-21 used Chromium 156 on Linux with this reported context:

```text
WebGL 2.0 / GLSL ES 3.00
ANGLE (Google, Vulkan 1.3.0
  (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver)
EXT_color_buffer_float present; MAX_TEXTURE_SIZE = 8192
```

This is a **software renderer**. These results establish execution and numeric
readback in a real WebGL API context. They do not establish hardware acceleration
or predict performance on an iPad, phone, integrated GPU, or discrete GPU.

Arithmetic cases use `abs-error <= 3e-6 + 3e-6 * abs(expected)`. The observed maximum
error was `7.450580596923828e-9`; position and vector-parameter cases matched
exactly for the tested values.

The initial universal tolerance test failed for `sin(1.25)` and `cos(1250)`:

| Operation | Clojure CPU | SwiftShader result | Absolute difference |
| --- | --- | --- | --- |
| `sin(1.25)` | 0.9489846193555862 | 0.9488597512245178 | 0.00012486813106837857 |
| `cos(1250)` | 0.9380365433953481 | 0.9379029273986816 | 0.00013361599666650292 |

These two cases now have a separate, explicitly labeled exploratory absolute
tolerance of `2e-4`, retaining relative tolerance `3e-6`. The arithmetic tolerance
was not relaxed. Passing this exploratory check is not approval for fine-DMX
parity, and two samples do not bound transcendental error across the domain.
The backend needs broader operator/domain tests and quantized-output comparison
before it can replace the CPU oracle for physical output.

GPU values are float32 while the CPU oracle generally uses float64. Constants
must fit float32, and operator domains must remain valid: division denominators
nonzero, square-root arguments nonnegative, and the documented power/clamp rules.
Long absolute millisecond clocks lose useful resolution in float32; prefer
relative time with a deliberate origin or a future split-time representation.
The runner rejects NaN/infinity but cannot infer every valid-domain constraint
from arbitrary compiled GLSL.

## Timing evidence and limits

The default measured corpus is the strict elapsed-time/parameter/position
arithmetic expression, with three warmups and twelve samples per size. Every
result was checked against the tiled Clojure oracle. The initial seven-case
verification run (before adding the musical-clock regression) observed:

| Positions | Total p50 | Total p95 | Fence wait p50 | Readback copy p50 |
| --- | --- | --- | --- | --- |
| 1,000 | 5.46 ms | 13.22 ms | 4.16 ms | 0.50 ms |
| 10,000 | 5.13 ms | 5.41 ms | 4.12 ms | 0.41 ms |

These are CPU wall-clock measurements around upload/submission, event-loop fence
polling, and readback copying. Browser timer clamping is visible in the roughly
4 ms wait increments. They are not GPU timer-query measurements. Twelve samples
are a smoke benchmark, not a tail-latency guarantee. Driver compilation appears
in cold runs and is warmed out of the table.

This expression-only workload excludes the JVM/browser boundary, command
reduction, effect state, assignment blending, fixture conversion, byte packing,
network/Art-Net/OLA, simulation rendering, and UI contention. It must not be
compared as a speedup over the full CPU render-frame benchmark. Compare the same
IR/operator workload on both backends and include transfer costs before choosing
an accelerator.

Chromium emitted a pixel-pack buffer shadow-copy performance warning during the
observed runs. Numerical checks still passed. Treat that driver behavior and
readback-copy overhead as unresolved performance investigation, rather than
claiming the readback path is fully optimized.

The automated harness also passed rejection/recovery checks for invalid inputs,
concurrent submission, cancellation, failed compilation retaining the old
program, unavailable contexts, expired deadlines, context loss, and disposal.
The later eight-case run also passed missing elapsed-beat, zero beats-per-bar,
and nonfinite bars-per-phrase rejection. Its musical vec3 output `[18, 2, 0.5]`
matched the Clojure oracle exactly on all 31 positions.

## Revalidate saved shader/oracle fixtures with Clojure

Run these forms from a Clojure REPL started in the Tolglow checkout. They check
that the HTML fixture still matches the current emitter/evaluator, rather than
allowing stale saved GLSL to make an unrelated interpreter look correct:

```clojure
(require '[afterglow.render.ir :as ir]
         '[clojure.data.json :as json]
         '[clojure.walk :as walk])

(def fixture-json
  (second (re-find #"(?s)<script id=\"oracle\" type=\"application/json\">(.*?)</script>"
                   (slurp "resources/gpu/test.html"))))
(def fixture (json/read-str fixture-json :key-fn keyword))
(defn expression-data [expression]
  (walk/postwalk
    (fn [node]
      (if (map? node)
        (reduce (fn [m k] (if (string? (get m k)) (update m k keyword) m))
                node [:op :key :axis :clock :type])
        node)) expression))
(defn rgba [type value]
  (case type
    :number [value value value 1.0]
    :vec2 (conj value 0.0 1.0)
    :vec3 (conj value 1.0)
    :vec4 value))

(doseq [test (:cases fixture)]
  (let [expression (expression-data (:expression test))
        emitted (ir/emit-glsl expression)
        evaluate (ir/compile-expression expression)
        expected (vec
                   (mapcat #(rgba (:type emitted)
                                  (evaluate {:position (vec %)
                                             :params (:params test)
                                             :time-ms (:timeMs test)
                                             :elapsed-ms (:elapsedMs test)}))
                           (partition 3 (:positions test))))]
    (assert (= (:source emitted) (get-in test [:shader :source])) (:id test))
    (assert (= expected (:expected test)) (:id test))))
```

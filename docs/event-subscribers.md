# Event subscribers and musical actions

A subscriber matches a committed show event, captures an ordered list of actions and plays it on the show clock. The same registrations run with Studio closed. Open **Debug** to inspect the events and see which subscriber IDs matched.

A kick can launch a random one-shot from two cue IDs. Half a bar later, it can bring the running intensity effects to full opacity.

```clojure
(studio/register-event-subscriber!
 runtime
 {:id :kick-accents
  :enabled? true
  :match {:type :audio/kick :category :audio}
  :actions [{:op :cue/launch
             :select {:ids [:ember :ice] :pick :random}
             :launch {:mode :one-shot :duration {:beats 1/2}}}
            {:op :instance/opacity
             :select {:categories [:intensity] :pick :all}
             :delay {:bars 1/2}
             :value 1.0}]})
```

Registration returns a command receipt. All three optional match fields intersect. Use `:emitter-id` to select one source. Empty match maps receive every eligible primary event. Actions generated by a subscriber carry `:event-subscriber` provenance so their own resulting control and effect events do not recursively launch subscribers.

| Action | Eligible candidates |
| --- | --- |
| `:cue/launch` | Published cues with available effect versions, including off-grid cues |
| `:effect/launch` | Current effect registry entries, including effects that have never been placed in a cue |
| `:instance/end` | Active instances, with their normal release behavior |
| `:instance/kill` | Active instances removed immediately |
| `:instance/opacity` | Active instances, with `:value` from 0 to 1 |
| `:callback` | The specified middleware function |

Use `:select {:pick :random}`, `:first` or `:all`. The default is seeded random selection. Candidates have a stable order independent of map iteration. Optional `:page-id`, `:ids` and `:categories` constrain the selection. Empty ID/category lists select nothing. Instance selectors accept instance, cue or effect IDs. A page limits direct effect launches to effects referenced by eligible cues on that page. A cue or effect marked with `:role :show-control`, `:kind :code-cue`, a corresponding tag, `:code-cue?` or `:show-control?` is excluded. The catalogue exposes eligible IDs for each picker. A one-shot defaults to one beat and can supply its own duration or parameter overrides.

Each step's optional `:delay` is relative to the preceding scheduled step and accepts beats, bars or phrases. Pausing transport freezes musical waits, and clock rebasing preserves remaining time on a seek. A registration edit or removal cancels its pending sequences. Restart clears pending runs. A full show save retains queued musical steps, selection RNG and paused progress. Restoring a run remaps references to active instances. Sequences waiting on an external callback at the instant of save are retired to avoid replaying work of uncertain completion.

## Middleware

A callback receives an immutable context and the original event. Return that context with edits to `:variables` and/or a vector of built-in `:actions`. Read the captured show through `:show`. Variable edits apply per key and detect concurrent changes. Actions returned by a callback run before the next authored step in that sequence.

```clojure
{:op :callback
 :implementation {:type :source :namespace "user" :bindings {"gain" 0.75}
                  :form "(fn [context event] (assoc-in context [:variables :last-accent] (* gain (get-in event [:data :confidence] 1))))"}}
```

A named function can use `{:type :var :symbol "my.show/on-accent"}`. Host-provided functions use `{:type :registered :id :accent}` with `:event-callback-options {:callbacks {:accent on-accent}}`. The REPL accepts a map with `:middleware #'my.show/on-accent` or `:middleware (fn [context event] ...)`. The Var and explicit source forms can be restored in another process. Inline closures need their implementation registered again there.

The host uses its configured reactive source trust policy for source and Var callbacks. Pass `:event-callback-options {:trusted-source? false}` to restrict event callbacks to host-registered functions. Two daemon workers run callbacks with a bounded queue. Expired, failed and stale callbacks leave the frame owner free to continue. The default deadline is one second. Interruptible user code can clean up on cancellation. A callback that ignores interruption can occupy its worker until it returns.

## Studio API

`GET /api/event-subscribers` returns event types, action names, eligible candidate IDs and registrations. `POST /api/event-subscribers` accepts `{:op :save :subscriber definition}` or `{:op :remove :id id}`. Include `:runtime-id` and `:expected-epoch` when editing from a live surface. Supply `:expected-subscriber` to compare against a prior definition. Explicit nil requires that the ID is new. Changes appear in the show-state push stream. The snapshot also reports queue drops and the last action error.

The owner admits up to 256 pending sequences across 128 registrations. Each sequence contains up to 32 steps. It applies up to 128 commands per cycle. A large `:all` operation continues from its saved target list and cursor, so later registry changes cannot substitute different targets halfway through an action.

# Tolglow master trust-boundary review

The source baseline was tolgraven/tolglow e87e43f5bd42da83779144afc8597be85b498bb9. The reviewed application path starts at tolglow.application/start-web and studio/listen!, passes through the Reitit Ring handlers in studio/web.clj, and reaches the owned show and resource managers. This review used static source inspection and contract tests with inert fixtures. No external device, provider, or running live show was exercised.

## Boundaries verified by inspection

- HTTP commands, query state, REPL eval and enabled developer facilities intentionally trust the operator’s Studio listener. A session ID associates state and held cues with a client. It is not an authentication token. At the audited master revision, a wildcard bind on a shared network gave peers operator access. The remediation adds the operator admission described below. An operator using a proxy must supply access control and preserve the public Host and scheme. See docs/studio-ui.md.
- tolglow.persistence/read-string bounds complete show documents to 16 MiB in UTF-8, reads one Transit or EDN document, and validates model/frame shape. EDN goes through clojure.edn/read. Raw credential fields are rejected. Native code, runtime handles and private keys do not belong to this schema. The REPL's explicit code evaluation path is separate from decoding a saved show.
- tolglow.fixtures.library/import-file bounds GDTF compressed payload and textual fixture input before dispatch to OFL/QXF/GDTF parsing. Library import yields an editable candidate. Installation and fixture patching are distinct explicit operations. This is a review of the Tolglow boundary. The downstream XML and archive decoders belong to the dependency's review.
- tolglow.repl.sessions/submit! is deliberately a trusted evaluator. Development workspace read/write operations resolve against owned roots and apply file limits. The Docker terminal and developer agent manager are host-configured capabilities. Studio is not an untrusted participant/player service.
- tolglow.agents/export-state keeps provider configuration and opaque references in shows. The actual secret remains local. The default credential file checks owner-only mode, validates its structure, and replaces contents atomically. Provider transport constructs bounded requests and does not follow redirects automatically.

## Coverage limits

No comprehensive fuzzing, network penetration testing, physical-device exercise, or external deployment review was performed. Browser same-origin checks complement the local listener and do not authenticate native clients. Exported shows may deliberately contain conversations and arbitrary user-authored data, so the secret-field validator cannot identify arbitrary sensitive prose in chat or effects.

## Operator admission follow-up

The listener now fails to start on a LAN interface unless authentication or the explicit trusted-lan? option is configured. Authenticated LAN listeners terminate TLS in Jetty or use a loopback TLS proxy for a fixed public origin. Studio challenges unauthenticated HTTP and WebSocket requests before routing. Safari and tablet browsers can use HTTP Basic credentials to obtain a signed HttpOnly, SameSite=Strict session cookie. Native clients can send Bearer credentials. The application gets the credential from a local environment variable. A 12-hour expiration and per-listener signing key bound session reuse.

The first JVM pass ran 78 tests and 627 assertions. A second pass ran 44 tests and 346 assertions, including the real Ring/Jetty listener, HTTP body limits, provider credential handling and both WebSocket upgrades. Both passes had zero failures and errors. A separate fresh Chromium context completed direct Jetty HTTPS sign-in, checked the Secure/HttpOnly/Strict cookie and used it for authenticated HTTP and both WSS upgrades. The Chromium QA used a generated local certificate. An actual iPad on a venue network and its trust configuration were not exercised.

Effective remediation commits include 8759489 (request/data trust), ae0b25d (authenticated listener), 81a35b0 (Push sign-in and cold/live defaults) and cd9536c (native operator sign-in). The Push capture worker accepts a named local token variable and supplies it only for its configured loopback webview origin. The iOS app, calibration clients and embedded WKWebView use the chosen venue origin and server realm to answer Basic authentication, with device-only Keychain storage. The Watch continues to use its OSC pairing. Cold/live plus Push JVM suites ran 24 tests and 140 assertions with zero failures, and seven Node worker tests passed. The native static manifest/contracts and rig checks passed; xcodebuild, Swift package execution, and native device credentials require Apple CI or a device for validation.

The native HTTP 401 guidance and WebView reconnect behavior are in `9cbb7d5`. The native source and rig contract checks passed. The cold and running show restore paths passed against the hardened Afterglow restore policy.

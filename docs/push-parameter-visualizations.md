# Parameter visualization on Push and Studio

The default parameter bank draws three-component vectors in three dimensions. The spatial widget labels the axes and the current components. It draws venue positions and direction vectors in the declared bounds. For a three-component vector with `:semantic/type :orientation` or `:rotation`, the axes show Euler rotations around X, Y and Z in that order; degrees are the default, and `:unit :radians` selects radians. A vector without bounds uses a symmetric power-of-two display range. The axis labels and numeric readout preserve the value’s units.

A colour never opens the spatial widget. A `:color` parameter, a `:gradient`, or a vector declared with `:semantic/type :rgb`, `:rgbw`, `:hsl` or another colour layout draws a swatch of the current value. Under the swatch, one gradient track per component shows the colours that component alone would produce, with the current amount marked. Studio shows red, green and blue. A Push encoder edits hue, saturation and brightness, so its tracks follow those components and mark the one the encoder turns. A touched colour widens into the free neighbouring encoder columns and adds the red, green and blue readout. Authored gradient stops draw as one ramp.

Studio and Push choose the widget through `tolglow.visualization.parameter-views`, shared ClojureScript and Clojure. `view-kind` returns `:color`, `:spatial`, `:history` or `:controls` for a schema and a requested view; `push-view`, `studio-view` and `monitor-view` apply it to each surface. `test/tolglow/visualization/parameter_views_test.clj` walks the default show, the portable example effects, the authoring recipes and a painted spatial volume, and checks that no colour parameter resolves to the spatial widget for any view preference or source state.

Open **Connections → Parameter visualization** to choose the full bank’s view. **Automatic by type** uses an effect parameter's optional `:visualization :history` or `:controls` preference. **3D space** applies to vectors; a colour keeps its swatch. **Time graph** plots the effective value received from the show for each continuous parameter. The **History window** zooms from half a beat to sixteen beats. Discrete controls keep their choices. The **Control values** view includes the existing component strips, dials and waveform picker previews. The captured-audio and material-trace display modes remain independently selectable.

In **Perform**, expand an effect and use **History** underneath a parameter. Use **Window** to zoom, **3D** to return to the spatial view on a vector and **Colour** to return to the swatch on a colour. Component editors, including the XYZ popover, continue to apply changes through the ordinary parameter commands.

History samples carry the show time and beat of the actual frame. A stopped beat stays at the same position while parameter edits replace its sample. Rewinding or switching instances starts a new trace. A plot keeps at most 256 samples at up to 10 Hz, and its lines connect the available observations. Missing values leave gaps. Closing the history, switching a Push bank or display mode, or hiding a Studio plot releases its history. The spatial view projects three coordinates on demand. When the visual scheduler lengthens the sampling interval under load, the moving marker interpolates between the two most recent observations. Euler axes take the shorter rotation. The numeric readout continues to show the actual parameter value.

## Reproduce the display check

Build the Studio with `npm run studio:build`, then run `lein run -m tolglow.qa.push-parameters`. The check starts a local preview show, records 48 parameter updates through the Push projection, captures the passive Chromium display, and edits a live vector through the touch layout. It saves the 960 × 160 frames and Studio screenshot under `target/push-parameter-qa`. Set `CHROMIUM` to the installed browser executable when it is outside `/usr/bin/chromium`.

# Documentation and work tracking

Keep observed behavior, implemented changes, proposals and research clearly separate.
Link source evidence to the surveyed revision and check local Markdown links.
Keep implementation status, prerequisites, ownership and verification on the
corresponding [GitHub issue](https://github.com/tolgraven/tolglow/issues).
Document benchmark costs excluded from measurement. Changes to shared runtime,
control, registry and rig schemas need coordinated consumer review.

## Continuing a request

Add refinements and acceptance checks to the existing issue. Link a separate
issue when the request introduces an independently deliverable feature. Record
the current owner and affected paths so agents can work independently. A
handoff should point to the branch, PR, verified revision and remaining work.
Close the issue once the linked change satisfies its acceptance checks.
